2. UMUMIY QOIDALAR

2.1 Base URL
- Global prefix yo'q
- Endpointlar to'g'ridan-to'g'ri ishlaydi

Misol:
- /auth/login2
- /users/me
- /companies/1

2.2 Authorization
Protected endpointlar uchun header:

Authorization: Bearer <accessToken>

2.3 Role va entity turlari

User role:
- SUPERADMIN
- ADMIN
- USER

Auth entityType:
- USER
- COMPANY

Izoh:
- token ichida `entityType` bo'ladi
- company login qilsa payload ichida `companyId` ham bo'ladi

2.4 Pagination
Backendda pagination ishlatiladigan joylarda query:
- page
- limit

Default:
- page = 1
- limit = 10

Maksimal:
- limit = 100

Pagination response ko'rinishi:
{
  "data": [],
  "meta": {
    "page": 1,
    "limit": 10,
    "total": 0,
    "totalPages": 0
  }
}

2.5 Validation qoidalari
- whitelist yoqilgan
- noto'g'ri field yuborilsa request rad qilinadi
- type transform yoqilgan
- integer fieldlarga string yuborilsa numberga aylantiriladi, agar valid bo'lsa

2.6 Telefon qoidasi
- `user.phone` va `company.phone` global unique
- userda bor telefon bilan company ochib bo'lmaydi
- companyda bor telefon bilan user ro'yxatdan o'ta olmaydi
- login paytida avval company qidiriladi, topilmasa user qidiriladi

2.7 Buffered interaction qoidasi
Quyidagi interactionlar buffer orqali yoziladi:
- apartment like
- master profile save
- master profile view

Qoidalar:
- 10 taga yetganda `createMany` bilan DB ga yoziladi
- response ichidagi count lar pending buffer bilan birga qaytishi mumkin
- toggle endpoint bir marta bosilganda save/like qo'shadi, yana bosilganda olib tashlaydi

2.8 Asosiy enumlar

OtpPurpose:
- REGISTER
- LOGIN

BannerLocation:
- HOME_TOP
- HOME_MIDDLE
- HOME_BOTTOM
- OTHER

LayoutStatus:
- AVAILABLE
- SOLD_OUT
- COMING_SOON

ApartmentListingType:
- SOTISH
- IJARA
- SHERIK_KERAK
- ALMASHISH

ApartmentDealStatus:
- ACTIVE
- SOLD

2.9 Xatolik kodlari
- 400 validation xato
- 401 token noto'g'ri yoki yo'q
- 403 ruxsat yo'q
- 404 topilmadi
- 409 duplicate yoki business conflict

2.10 Umumiy success response
Ko'p endpointlar to'g'ridan-to'g'ri object qaytaradi.
Ba'zi endpointlar `message` bilan qaytadi.
Ba'zi list endpointlar pagination bilan qaytadi.

USER qila oladi:
- register
- login
- o'z profilini update
- master profile create/update/delete
- rating create/update/delete faqat o'ziniki
- apartment create/update/delete agar o'ziniki bo'lsa
- apartmentni SOLD qilish agar o'ziniki bo'lsa
- apartmentga like toggle
- master profilen save toggle
- masterga contact bosish
- favorite apartments va saved masters ni ko'rish

16.2 ADMIN
ADMIN qila oladi:
- userlarni ko'rish
- user block/unblock
- user archive/unarchive
- user delete
- regions CRUD
- banners CRUD va status
- job category CRUD, archive, unarchive, status toggle
- apartment category CRUD
- company create/delete/status
- dashboard ko'rish
- company, complex, layout, apartmentlarni boshqarish

16.3 SUPERADMIN
SUPERADMIN huquqlari ADMIN bilan bir xil yoki undan yuqori.

16.4 COMPANY
COMPANY token qila oladi:
- login
- o'z companysini update
- o'z companysiga tegishli complex CRUD
- o'z companysiga tegishli apartment layout CRUD

17. FRONTEND UCHUN MUHIM FLOWLAR

17.1 User register flow
1. `POST /auth/send-otp`
2. `POST /auth/register`
3. accessToken va refreshToken saqlanadi

17.2 User OTP login flow
1. `POST /auth/send-otp`
2. `POST /auth/login`

17.3 User password login flow
1. `POST /auth/login2`

17.4 Master bo'lish flow
1. user login qiladi
2. job categorylarni oladi `GET /job-categories`
3. formda `categoryIds` bilan `POST /master-profiles`

17.5 Ustani saqlash flow
1. detailni oladi `GET /master-profiles/:id`
2. icon bosilganda `POST /master-profiles/:id/save`
3. state uchun `GET /master-profiles/:id/interaction`

17.6 Ustaga bog'lanish flow
1. detail ochilganda `POST /master-profiles/:id/view`
2. bog'lanish tugmasida `POST /master-profiles/:id/contact`

17.7 Uyga like flow
1. detail yoki card chiqariladi
2. state uchun `GET /apartments/:id/interaction`
3. like tugmasida `POST /apartments/:id/like`

17.8 Uy sotildi flow
1. owner o'z apartmentini ochadi
2. `PATCH /apartments/:id/status`
3. body: `{ "dealStatus": "SOLD" }`

17.9 Company detail analytics flow
1. list `GET /companies`
2. detail `GET /companies/:id`
3. view count uchun `POST /companies/:id/view`

18. BUSINESS RULELAR

18.1 Rating qoidasi
- bitta user bitta ustaga bitta rating
- o'ziga o'zi rating yo'q

18.2 Master category qoidasi
- bitta usta bir nechta categoryada bo'lishi mumkin
- `categoryIds` array bilan boshqariladi

18.3 Like va save qoidasi
- toggle endpoint
- duplicate yozuv yo'q
- bitta user bitta entityga bitta interaction

18.4 Apartment owner qoidasi
- apartment update/delete/status ni owner yoki admin qiladi

18.5 Company access qoidasi
- company token faqat o'z companysi ustida ishlaydi
- owner user ham faqat o'zinikini boshqaradi
- admin va superadmin istalgan companyni boshqaradi

18.6 Banner image qoidasi
- banner image `multipart/form-data` bilan yuboriladi
- URL emas, haqiqiy fayl bo'lishi kerak

19. FRONTENDGA TAVSIYA

Frontendda quyidagilarni saqlash kerak:
- accessToken
- refreshToken
- entityType

Frontend har doim quyidagini tekshirib ishlasin:
- usermi yoki companymi
- role nimadaligi
- ownership kerak endpointlarda current login egasini tekshirish
